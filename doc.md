# finance — подробная документация

Документ описывает фактически реализованное поведение версии 0.2.

## 1. Архитектура

```
main.py  ──► excel_parser.py  ──► calc.py  ──► draw.py
   │                              ▲              │
   └──────── .env ────────────────┘              ▼
                                         окно matplotlib
```

* `excel_parser.py` — I/O, чтение Excel, валидация колонок, приведение типов.
* `calc.py` — финансовое ядро: dataclass-структуры, проценты, временные
  преобразования, формулы целей, аналитические функции.
* `draw.py` — matplotlib-визуализация. Никаких расчётов. Графики
  показываются через `plt.show()` — пользователь сам решает, сохранять ли.
* `main.py` — CLI, чтение `.env`, автозагрузка данных при старте
  (bootstrap), маршрутизация пунктов меню.

Все исходники лежат в `src/`. Точка входа — `python src/main.py`
или `start.bat`.

## 2. Входные Excel-файлы

| категория 2                | str     | подкатегория                            |

В версии 0.2 поле «норма расхода на 1 ед.» удалено.

### 2.2. Портфель

|--------------------------|-------|---------------------------------------|

## 3. Формат процентов

Все проценты в Excel и `.env` хранятся как «число процента»: `6` означает
6%, а не 0.06. Внутри `calc.py` сразу нормализует значения функцией
`to_fraction`.

## 4. Временная база

* Расходы — **в месяц**.
* Доходность портфеля — **годовая номинальная**.
* Инфляция — **годовая**, % (хранится в `.env`, в текущей версии не
  подмешивается в формулы автоматически — оставлена для будущих версий).
* Срок — возвращается в **годах, месяцах и днях** (1 месяц = 30 дней).

Перевод годовой ставки в месячную — **геометрическая конвенция**:

    r_month = (1 + r_annual)^(1/12) − 1

Это стандартная модель, согласующаяся со сложным процентом.

## 5. Финансовые формулы

### 5.1. Ожидаемая доходность портфеля

    expected = Σ (weight_i / Σ weights) · return_i

Налоги и комиссии **не** вычитаются автоматически — пользователь задаёт
уже «чистую» ожидаемую доходность. Дополнительно доступна функция
`portfolio_after_costs_percent`, которая вычитает налог/комиссию по
каждой строке — её результат показан в CLI, но в формулы целей
по умолчанию идёт gross-доходность.

### 5.2. Срок до целевого капитала

    n_months = log(target / capital) / log(1 + r_month)

Применяется, если текущий капитал < целевого и доходность > 0.

### 5.3. Срок до целевого пассивного дохода

    current_income = capital · r_month
    ratio          = target_monthly / current_income
    n_months       = log(ratio) / log(1 + r_month)

Если текущий месячный доход уже покрывает цель — срок 0.

### 5.4. Срок с учётом расходов

Модель: ежемесячно пассивный доход `C·r_month` уменьшается на расходы.
Дискретный закон капитала:

    C(n) = (C₀ − E/r) · (1 + r)ⁿ + E/r

где `E` — месячные расходы, `r` — месячная ставка. Решение относительно n:

    n = log((target − E/r) / (C₀ − E/r)) / log(1 + r)

Если `E > C₀ · r` (расходы превышают пассивный доход) — капитал
уменьшается, цель **недостижима**.

### 5.5. Необходимый капитал под пассивный доход

    capital = target_monthly / r_month

### 5.6. Необходимый месячный доход под цель за N лет

    r_month      = exp(log(target / current) / (years·12)) − 1
    monthly_income = current · r_month

Результат — пара: `monthly_income` и эквивалентная `annual_return_percent`.

## 6. Обработка edge cases

| Случай                                | Поведение                                |
|---------------------------------------|------------------------------------------|
| Цель уже достигнута                   | срок = 0, achievable=True                |
| Целевой капитал = 0                   | срок = 0, achievable=True                |
| Доходность = 0 при росте              | achievable=False, явное сообщение        |
| Доходность < 0                        | achievable=False                         |
| Капитал = 0 при росте                 | achievable=False                         |
| Расходы > пассивного дохода           | achievable=False                         |
| Некорректные параметры в формулах     | ValueError с понятным текстом            |
| Доли портфеля ≠ 100% (±0.5%)          | ExcelParseError при загрузке             |
| CURRENT_CAPITAL = 0                   | валидная конфигурация, считается как «капитал ещё не накоплен» (формулы вернут «недостаточный капитал» при росте цели) |

## 7. CLI

Меню:

1. Показать расходы
2. Портфель: ожидаемая доходность
3. Время достижения цели по капиталу
4. Необходимый доход
5. График: структура расходов
6. График: срок vs капитал/доходность
7. График: срок vs расходы
0. Выход

Данные загружаются автоматически при старте (после bootstrap и
валидации). Пунктов «загрузить расходы» / «загрузить портфель» нет —
это намеренно.

Пункты меню описаны в `MENU` (dict) — добавление новой функции
сводится к двум строкам: новой функции и одной записи в `MENU`.

## 8. Поведение при ошибках

* **Отсутствует `.env`** — приложение выводит понятное сообщение,
  `start.bat` добавляет паузу «Нажмите любую клавишу чтобы выйти».
* **CURRENT_CAPITAL=0** — валидно; формулы корректно обрабатывают
  крайние случаи («недостаточный начальный капитал»).
* **Ошибка конфигурации/Excel** — то же поведение, что и при отсутствии
  `.env` (сообщение + пауза в `start.bat`).

## 10. Допущения

* Единственный источник месячной суммы — `норма расхода на 1 мес`
  (поле `норма расхода на 1 ед.` удалено в 0.2).
* Доходность — годовая номинальная, сложный процент.
* Модель «жизнь на доход от капитала» — без внешних пополнений.
* Инфляция пока только хранится в `.env`, в формулы не подмешивается.
* «Текущий месячный доход» (зарплата) в v1 не вычитается из цели —
  цель всегда по пассивному доходу.

## 11. Ограничения первой версии

* Нет инфляционной коррекции (значение хранится, но не используется).
* Нет Monte Carlo, VaR, оптимизации портфеля.
* Нет поддержки пополнений/изъятий во время накопления.
* Один набор расходов / один портфель за сессию (после изменения
  файлов нужно перезапустить CLI).
